# olympiad-lean4

A curated collection of machine-verified competition mathematics in Lean 4,
supported by Mathlib and a small reusable utility library. The aim is to make
each formalization faithful to its original statement and independently readable.
Problems are selected and formalized manually; initialization includes only a
small development example, with no competition solutions.

Supported competitions: International Mathematical Olympiad (IMO), Asian Pacific
Mathematics Olympiad (APMO), Balkan Mathematical Olympiad (BMO), and Junior Balkan
Mathematical Olympiad (JBMO).

## Workspace

```text
Olympiad/
  Utils/{NumberTheory,Algebra,Inequalities,Combinatorics,Geometry}.lean
  Problems/{IMO,APMO,BMO,JBMO}/       # e.g. IMO/Y2023/P3.lean
  Examples/Starter.lean              # development demonstration
Olympiad.lean                       # utilities, example, completed problems
templates/Problem.lean
scripts/new_problem.py
.github/workflows/lean.yml
.vscode/extensions.json
lakefile.toml
lean-toolchain
lake-manifest.json                 # generated by Lake; commit after setup
```

Lean and Mathlib are pinned to the matching stable release **v4.34.1**. Lake is
bundled with Lean; Elan selects the version in `lean-toolchain`. The configuration
follows Lake's official `math` template, with an explicit `Olympiad` root and
warnings treated as errors. Mathlib's copyright/license header, empty-line, and
whitespace style linters are disabled; the other standard Mathlib linters stay enabled.

## Installation and setup

Install Git, Python 3, [Elan](https://github.com/leanprover/elan), and
[VS Code with the Lean 4 extension](https://leanprover-community.github.io/install/).
On macOS or Linux, the official Elan installer is:

```bash
curl --fail -sSf https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh
```

Open a fresh terminal after installation. From the repository root:

```bash
elan self update
elan toolchain install leanprover/lean4:v4.34.1
lake update
lake exe cache get
lake build
code .
```

`lake update` resolves the pinned Mathlib tag and writes `lake-manifest.json`,
including exact Git revisions for all transitive dependencies. Commit this file
to make subsequent checkouts reproducible. On an already initialized checkout,
use `lake exe cache get` and `lake build`; do not routinely run `lake update`.
Upgrade Lean and Mathlib together, regenerate the manifest, and verify the build.

If `code` is unavailable on macOS, open VS Code and run **Shell Command: Install
'code' command in PATH** from its command palette, or open this folder using
**File → Open Folder**. Always open the repository root so the extension sees
the toolchain and Lake configuration.

The workspace has been verified with Lean/Mathlib 4.34.1: `lake build` succeeds,
including all five utilities, the starter example, and the root library. The
template and a generated draft also pass `lake env lean`. Elan is updated to
4.2.4, Mathlib's precompiled cache is downloaded, the dependency manifest is
present, and local Git is initialized. No remote is configured. CI requires the
manifest rather than silently creating a new lockfile.

## Formalizing a problem

```bash
python3 scripts/new_problem.py IMO 2023 3
code Olympiad/Problems/IMO/Y2023/P3.lean
lake env lean Olympiad/Problems/IMO/Y2023/P3.lean
```

The generator accepts the four competition abbreviations, a four-digit year from
the competition's first year onward, and problem numbers 1–6 for IMO, 1–5 for
APMO, or 1–4 for BMO/JBMO. It validates identifiers rather than confirming whether
a particular edition occurred. It works from any current directory and refuses
to overwrite an existing file. `python` can replace `python3` if it selects Python 3.

Fill in the original statement, official source, informal strategy, explicit
assumptions, local helpers, and main theorem. Replace the initial `Init` import
with the precise Mathlib and utility modules actually needed. Namespaces follow
`Olympiad.Problems.IMO.Y2023.P3`; use descriptive `snake_case` theorem names.
The empty draft and template parse, but contain no claimed mathematical result.

Check individual drafts with `lake env lean path/to/Problem.lean`. This command
checks the file; it does not build missing imported project modules. Run
`lake build` first for shared dependencies. Once a problem is complete, add its
import to `Olympiad.lean` and update the index below. Only the root and its imports
are included in the default build, so new drafts are not published automatically.

Build the curated library, utilities, and example with:

```bash
lake build
```

## Proof standards

- Every completed problem must compile and faithfully represent the original
  competition statement, with all assumptions explicit.
- Completed proofs must contain neither `sorry` nor `admit`. Do not introduce
  unproved project-specific axioms. Lean's standard foundational axioms are allowed.
- Include a brief explanation of the mathematical strategy and an official source.
- Search Mathlib before proving a new utility; use existing results and tactics.
- Extract genuinely reusable results into the appropriate domain module. Prefer
  small composable lemmas, consistent names, and documented non-obvious assumptions.
- Keep competition-specific arguments local and imports minimal. Utilities must
  not import problems; avoid circular dependencies.

GitHub Actions runs on pushes and pull requests to `main`. The established
`leanprover/lean-action` installs the pinned toolchain, restores/downloads caches,
and runs `lake build`. A conservative source check rejects `sorry`, `admit`,
`axiom`, and `sorryAx` tokens in all project Lean files, including drafts and
comments. Keep prose mentioning these tokens outside Lean source files. This
check is a source policy guard, not a semantic audit of theorem statements;
mathematical fidelity still requires review.
